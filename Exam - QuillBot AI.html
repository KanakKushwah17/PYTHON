Parse Tree

A parse tree is a tree-like representation that shows how a string or expression is generated from the grammar of a language. It is also called a syntax tree. Parse trees are mainly used in compiler design to check whether the input follows the grammar rules of the programming language.

In a parse tree:

  • The root node represents the start symbol of the grammar.

  • The internal nodes represent non-terminal symbols.

  • The leaf nodes represent terminal symbols or actual input symbols.

A parse tree clearly shows the hierarchical structure of the input and the order in which productions are applied.

Example of Parse Tree

Consider the arithmetic expression:

a + b * c

Grammar:

Explanation

  1. The root node is E because expression is the start symbol.

  2. The expression is divided into E + T.

  3. The left side generates a.

  4. The right side generates b * c.

  5. The tree shows that multiplication has higher precedence than addition.

Uses of Parse Tree

  1. It helps the compiler understand the structure of the program.

  2. It is used for syntax analysis in compiler design.

  3. It checks whether the input string is grammatically correct.

  4. It helps in translation and code generation.




Recognition of Token Process

The recognition of tokens is an important function of the lexical analyzer in a compiler. A token is the smallest meaningful unit of a program, such as keywords, identifiers, operators, constants, and punctuation symbols.

The process of token recognition involves scanning the source program character by character and grouping characters into valid tokens.

Steps in Token Recognition Process

1. Reading Source Program

The lexical analyzer reads the input program from left to right, one character at a time.

Example:

int a = 10;

2. Grouping Characters into Lexemes

Characters are grouped together to form meaningful strings called lexemes.

Example:

LexemeMeaningintKeywordaIdentifier=Operator10Constant;Separator

3. Matching Patterns

Each lexeme is compared with predefined patterns or rules to determine its token type.

Examples:

  • int → Keyword token

  • a → Identifier token

  • 10 → Number token

These patterns are usually defined using regular expressions.

4. Generating Tokens

After identification, the lexical analyzer generates tokens and passes them to the syntax analyzer.

A token generally has:

  • Token name

  • Attribute value

Example:

<KEYWORD, int>
<ID, a>
<ASSIGN_OP, =>
<NUMBER, 10>

Example of Token Recognition

Consider the statement:

sum = a + b;

The lexical analyzer recognizes the following tokens:

LexemeTokensumIdentifier=Assignment OperatoraIdentifier+Arithmetic OperatorbIdentifier;Separator

Role of Finite Automata in Token Recognition

Finite Automata are used to recognize tokens efficiently.

  • The lexical analyzer moves through different states based on input characters.

  • When a final state is reached, a token is recognized.

For example:

  • A sequence of letters and digits beginning with a letter is recognized as an identifier.

  • A sequence of digits is recognized as a number.

Advantages of Token Recognition

  1. Simplifies syntax analysis.

  2. Detects lexical errors.

  3. Removes unnecessary spaces and comments.

  4. Improves compilation efficiency.





Phases of Compiler

A compiler is a special system software that translates a program written in a high-level programming language such as C, C++, or Java into machine language that can be understood and executed by the computer. The process of translation is performed step by step through different stages known as phases of a compiler.

Each phase performs a specific operation on the source program and passes its output to the next phase. The compiler checks the program for errors, analyzes its structure and meaning, optimizes it, and finally generates machine code.

The different phases of a compiler work together to make the translation process accurate, efficient, and fast. These phases are:

  1. Lexical Analysis

  2. Syntax Analysis

  3. Semantic Analysis

  4. Intermediate Code Generation

  5. Code Optimization

  6. Code Generation

In addition to these phases, two important activities are performed throughout the compilation process:

  • Symbol Table Management

  • Error Handling

1. Lexical Analysis (Scanner)

Lexical Analysis is the first phase of the compiler. In this phase, the source program is read character by character and converted into meaningful units called tokens. The lexical analyzer removes unnecessary spaces, comments, and line breaks from the program.

Tokens may include:

  • Keywords

  • Identifiers

  • Constants

  • Operators

  • Special symbols

The lexical analyzer acts as an interface between the source code and the parser.

Example

Source Program:

int a = 10;

Tokens Generated:

<KEYWORD, int>
<ID, a>
<ASSIGN_OP, =>
<NUMBER, 10>
<SEMICOLON, ;>

Functions of Lexical Analyzer

  • Reads source code

  • Identifies tokens

  • Removes white spaces and comments

  • Reports lexical errors

2. Syntax Analysis (Parser)

Syntax Analysis is the second phase of the compiler. In this phase, the parser checks whether the sequence of tokens follows the grammatical rules of the programming language. It determines whether the statement is syntactically correct or not.

The parser builds a parse tree or syntax tree representing the structure of the program.

Example

Correct Statement:

a = b + c;

Incorrect Statement:

a + = b;

The parser detects syntax errors such as missing semicolons, unmatched brackets, or incorrect arrangement of tokens.

Functions of Syntax Analyzer

  • Checks grammar rules

  • Builds parse tree

  • Detects syntax errors

3. Semantic Analysis

Semantic Analysis checks the meaning of the program statements after syntax analysis. Even if the syntax is correct, the meaning of the statement must also be valid.

This phase checks:

  • Type compatibility

  • Variable declarations

  • Function usage

  • Scope rules

Example

int a;
a = "Hello";

This statement is syntactically correct but semantically wrong because a string value cannot be assigned to an integer variable.

Functions of Semantic Analyzer

  • Type checking

  • Verifies declarations

  • Checks compatibility of operations

  • Detects semantic errors

4. Intermediate Code Generation

After semantic analysis, the compiler generates an intermediate form of the source code. This code is machine-independent and can be easily converted into machine code later.

The intermediate code helps simplify the compilation process.

Example

Expression:

a = b + c * d

Intermediate Code:

t1 = c * d
t2 = b + t1
a = t2

Functions

  • Produces intermediate representation

  • Makes optimization easier

  • Separates front-end and back-end of compiler

5. Code Optimization

Code Optimization improves the intermediate code to make the program run faster and use less memory. It removes unnecessary operations and produces efficient code.

Optimization does not change the output of the program.

Example

Before Optimization:

x = 2 * 5

After Optimization:

x = 10

Functions

  • Reduces execution time

  • Removes redundant code

  • Improves efficiency

6. Code Generation

Code Generation is the final phase of the compiler. In this phase, the optimized intermediate code is converted into machine code or assembly language.

The generated machine code can be directly executed by the computer.

Example

MOV R1, a
ADD R1, b
STORE R1, c

Functions

  • Generates machine instructions

  • Allocates memory and registers

  • Produces target code

Symbol Table Management

The symbol table is a data structure used by the compiler to store information about identifiers used in the program.

It stores:

  • Variable names

  • Data types

  • Scope information

  • Memory addresses

Example

IdentifierTypeScopeaintlocalbfloatglobal

The symbol table is used in almost every phase of the compiler.

Error Handling

Error handling is an important activity of the compiler. Errors may occur during any phase of compilation. The compiler detects these errors and displays meaningful messages to the programmer.

Types of Errors

  1. Lexical Errors
    Example: Invalid symbols

  2. Syntax Errors
    Example: Missing semicolon

  3. Semantic Errors
    Example: Type mismatch

Efficient error handling helps programmers debug programs easily.

Data Structures Used in Compiler

A compiler uses different types of data structures to store, organize, and process information during compilation. These data structures help the compiler perform lexical analysis, syntax analysis, semantic analysis, code optimization, and code generation efficiently.

The main data structures used in a compiler are:

  1. Symbol Table

  2. Tree

  3. Stack

  4. Queue

  5. Graph

  6. Hash Table

  7. Linked List

1. Symbol Table

The symbol table is the most important data structure used in a compiler. It stores information about identifiers used in the program.

Information Stored

  • Variable names

  • Function names

  • Data types

  • Scope information

  • Memory locations

Example

  • Used in semantic analysis

  • Helps in type checking

  • Helps in code generation

2. Tree Data Structure

Trees are widely used in syntax analysis.

Types

  • Parse Tree

  • Syntax Tree

  • Expression Tree

A tree represents the hierarchical structure of the program.

Example

Expression:

a + b * c

Syntax tree:

/ \
a *

b c

Uses

  • Expression evaluation

  • Syntax analysis

  • Intermediate code generation

3. Stack

A stack follows the LIFO (Last In First Out) principle.

Uses in Compiler

  • Syntax parsing

  • Expression evaluation

  • Function call management

Example

During parsing, symbols are pushed and popped from the stack.

4. Queue

A queue follows the FIFO (First In First Out) principle.

Uses

  • Handling compiler tasks

  • Breadth-first traversal

  • Scheduling operations

5. Graph

Graphs are used in code optimization and control flow analysis.

Uses

  • Representing flow of control

  • Dependency analysis

  • Register allocation

Example

6. Hash Table

Hash tables are used to implement symbol tables efficiently.

Advantages

  • Fast searching

  • Fast insertion and deletion

Uses

  • Quick access to identifiers

7. Linked List

Linked lists are used for dynamic memory management.

Uses

  • Managing tokens

  • Storing intermediate code

  • Maintaining symbol table entries




Dead Code Elimination and Its Effect on Performance

Dead Code Elimination

Dead code elimination is a code optimization technique used in compiler design to remove unnecessary or useless code from a program. Dead code refers to those statements or instructions that do not affect the final output of the program.

Such code may:

  • Never be executed

  • Produce values that are never used

  • Become unnecessary after optimization

By removing dead code, the compiler makes the program smaller and more efficient.

Example of Dead Code

int a = 10;
int b = 20;
int c = a + b;
c = 50;
printf("%d", c);

In this example:

int c = a + b;

is dead code because the value of c is immediately replaced by:

c = 50;

The previous calculation has no effect on the final output.

After dead code elimination:

int a = 10;
int b = 20;
int c = 50;
printf("%d", c);

Types of Dead Code

1. Unreachable Code

Code that can never execute.

Example:

return 0;
printf("Hello");

The printf statement will never run.

2. Unused Variables or Computations

Values calculated but never used.

Example:

x = y + z;

If x is never used later, this statement is dead code.

Effect on Performance

Dead code elimination improves program performance in many ways.

1. Reduces Program Size

Removing unnecessary instructions decreases the size of executable code.

2. Increases Execution Speed

The processor executes fewer instructions, so the program runs faster.

3. Reduces Memory Usage

Less code requires less memory and storage space.

4. Improves CPU Efficiency

The CPU spends less time executing useless operations.

5. Better Optimization

Simpler code allows other optimization techniques to work more effectively.

Advantages of Dead Code Elimination

  • Produces efficient programs

  • Reduces compilation overhead

  • Saves system resources

  • Improves overall performance

Disadvantages

  • Additional analysis may increase compiler complexity

  • Sometimes difficult to detect all dead code in large programs



DAG Representation of Basic Block

A DAG (Directed Acyclic Graph) is a graphical representation used in compiler optimization to represent the computations inside a basic block. It helps in identifying common subexpressions, eliminating redundant calculations, and improving code efficiency.

A DAG is:

  • Directed because edges have directions.

  • Acyclic because it does not contain any cycle.

In compiler design, DAG representation is mainly used during code optimization.

Basic Block

A basic block is a sequence of consecutive statements in which:

  • Control enters at the beginning.

  • Control leaves at the end.

  • No branching occurs inside the block.

Example

a = b + c
d = b + c
e = a - d

This is a basic block because statements execute sequentially without interruption.

DAG Representation

In a DAG:

  • Leaf nodes represent identifiers or constants.

  • Interior nodes represent operators.

  • Edges represent relationships between operands and operators.

The DAG stores only one copy of repeated expressions.

Example of DAG Construction

Consider the basic block:

a = b + c
d = b + c
e = a - d

Step 1: Create nodes for operands

b c

Step 2: Create node for expression b + c

(+)
/ \
b c

This node is shared by both a and d.

Step 3: Assign labels

(+)
/ \
b c
/ \
a d

Step 4: Create node for a - d

(-)
/ \
a d
\ /
(+)
/ \
b c

e is associated with the subtraction node.

Advantages of DAG Representation

1. Eliminates Common Subexpressions

Repeated expressions are calculated only once.

Example:

b + c

is computed once and reused.

2. Reduces Redundant Calculations

Avoids unnecessary computations.

3. Improves Code Optimization

Helps in:

  • Dead code elimination

  • Constant folding

  • Common subexpression elimination

4. Generates Efficient Machine Code

Produces optimized intermediate code.

Applications of DAG

  • Compiler optimization

  • Intermediate code generation

  • Detecting redundant expressions

  • Improving execution speed
